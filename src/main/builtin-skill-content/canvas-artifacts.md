# 画布成品：让结果直接可见、可迭代、可导出

## 何时使用

- 要交付网页、报告页、图表、SVG、Markdown 文档或代码片段。
- 用户希望「直接看到成品」，而不是只拿到文件路径。
- 需要迭代视觉/内容，并保留版本、导出或保存到工作区。
- 适合单文件、自包含、可离线打开的成品。

## 何时不要用

- 需要完整工程/构建链的多文件应用：写到工作区并运行，不要硬塞进画布。
- 二进制大文件（视频、超大 PDF、Office 原件）：用文件预览/系统程序，不按文本读入画布。
- 需要用户登录/后端交互的应用：画布只是前端静态成品，说明限制。

## 画布支持什么

| 类型 | 适合 | 注意 |
|---|---|---|
| HTML | 报告、落地页、交互式图表、小游戏 | 单文件、自包含、离线可开；脚本可交互但拿不到宿主数据 |
| Markdown | 说明、方案、轻量报告 | 适合阅读，不适合复杂版式 |
| SVG | 图标、插画、数据图 | 文本格式，注意尺寸与可访问性 |
| code | 代码展示、配置、脚本片段 | 指定语言高亮 |
| text | 日志、纯文本、CSV 预览 | 大文件会被截断 |
| file | 图片/PDF/Office/音视频 | 走只读预览，不要按 UTF-8 读 |

画布文本成品有 2MB 级限制；大文件写到工作区，用文件预览或系统程序打开。

## 工作流程

### 1. 选格式

- 以阅读为主、结构简单 → Markdown。
- 需要版式、图表、交互、打印 → HTML。
- 图形/图标 → SVG。
- 代码展示 → code。
- 图片/PDF/Office → 文件预览 + open_artifact(path)。

不要为了「看起来高级」把简单说明做成复杂 HTML；也不要为了省事把复杂报告塞进 Markdown 表格。

### 2. 写到工作区

- 用 write_file 写文件（推荐），大内容分段写；不要一次塞超长字符串。
- 路径放在工作区内，例如 artifacts/report.html；不要写到系统目录。
- 文件名用英文/数字/短横线，标题可以是中文。
- HTML 必须单文件：CSS/JS 内联；图片用 data URI 或内联 SVG；不依赖外部 CDN（离线/内网也能打开）。

### 3. 用 open_artifact 展示

- 传 path 指向刚写好的文件；或小内容直接传 content。
- kind 可省略，按扩展名推断；HTML 用 html，Markdown 用 markdown。
- 同一路径/同一内联标题会更新已有成品，不会重复堆卡片；迭代后重新打开让用户看到最新版。
- 写完后立即打开，不要只告诉用户「文件在某个路径」。

### 4. 在画布检查

- HTML：真实渲染、脚本执行、没有空白/错误页；滚动正常；宽窄屏可用。
- Markdown：标题层级、表格、代码块、链接。
- SVG：尺寸、留白、颜色、可访问标题。
- 文件预览：图片/PDF/Office 能打开，不是乱码或空白。
- 深色/浅色主题下都检查（成品自身主题可与应用不同，但不能不可读）。

### 5. 迭代

- 先改内容与结构，再改视觉；每次改动后重新打开同一产物。
- 需要保留旧版时，用工作区文件副本或画布的版本历史（文本成品）。
- 大幅改版前先确认方向；不要把用户已经认可的版本直接覆盖到无法回退。

### 6. 导出与保存

- 画布可导出 HTML / Markdown / 纯文本 / PDF；导出前确认版式、分页、图片。
- 内联成品可「保存到文件夹」，写入工作区 artifacts/ 并回写路径。
- 已有文件的成品可「在文件夹中显示」或在系统程序中打开。
- 需要在 Morrow 内置浏览器查看时，用「在内置浏览器中预览」，不要依赖外部 Edge。

## HTML 成品规范

- 单文件、自包含：内联 CSS/JS；字体用系统栈或 data URI；图片内嵌。
- 响应式：至少 390px、768px、1440px 三档；窄屏不横向滚动。
- 打印：A4 页边距、避免标题孤立、表格不截断、关键内容不被分页切断；需要时加 @media print。
- 可访问性：语义标签、标题层级、alt、键盘可达、焦点可见、对比度足够。
- 交互：按钮有真实结果；加载/空/错误状态可见；不要留下死链接或占位按钮。
- 数据：图表数字与正文一致；坐标轴/单位/来源清楚；不要用外部接口（画布环境不应依赖网络）。
- 安全：不读取宿主 localStorage/DOM；外部链接交给宿主打开；不要在成品里嵌入密钥。

## Markdown 成品规范

- 标题层级从 # 开始，不跳级。
- 长文档加目录；表格不要过宽；代码块标注语言。
- 链接用可点击的相对/绝对路径；引用保留来源。
- 需要复杂版式/图表时改用 HTML。

## 成品质量检查

- 用户打开画布，第一眼能看到成品，而不是加载中/空白/报错。
- 主路径可操作，按钮/链接有结果。
- 内容完整，没有占位符/TODO/假数据。
- 宽窄屏、明暗主题、打印预览都检查。
- 文件名、标题、正文术语一致。
- 更新后用户看到的是最新版本。
- 导出文件能打开，内容与画布一致。

## 常见反模式

- 只写文件不打开画布，用户不知道成品在哪。
- HTML 依赖外部 CDN，离线打开样式/脚本全丢。
- 把二进制文件按文本读入画布，显示乱码。
- 成品超过 2MB 仍硬塞画布，被截断。
- 每次迭代新建一个成品，画布堆满重复卡片。
- 按钮没有行为、链接是占位符。
- 只做桌面，窄屏溢出。
- 导出后不检查，PDF 截断表格/图片。
