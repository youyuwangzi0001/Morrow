# 工作区与 Git：在边界内改动，留下可追溯的历史

## 何时使用

- 需要读取、创建、修改或删除工作区文件。
- 需要查看 diff、提交、创建/切换分支、查看历史或回退。
- 用户要求「提交」「看看改了什么」「回到某个版本」「在分支上做」。
- 需要判断某个文件是否在工作区内、是否被忽略、是否已被修改。

## 何时不要用

- 纯对话/资料查询，不涉及文件：不需要。
- 需要操作工作区外的文件：先征得授权，默认不越界。
- 破坏性 Git 操作（reset --hard、force push、删除分支）：必须单独确认。

## 工作区边界

- 默认只读写当前工作区；相对路径以工作区根为基准。
- 不读取系统目录、其他用户目录、凭据文件或工作区外路径，除非用户明确授权并说明范围。
- 不跟随符号链接/junction 越界；不确定时先 realpath 校验。
- 删除前确认目标；Morrow 的 delete_file 会备份并生成可回退的删除记录。
- 不把密钥、令牌、用户数据写进项目文件、日志、提交或截图。

## 文件操作

| 目的 | 工具 | 注意 |
|---|---|---|
| 看目录 | list_dir | 不要凭记忆猜结构 |
| 找文件 | glob | 先缩小范围 |
| 搜内容 | grep | 支持目录或单文件 |
| 读文本 | read_file | 二进制用专用工具 |
| 新建/整体重写 | write_file | 大文件分段；不要覆盖未读过的文件 |
| 局部修改 | edit_file | old_string 必须与原文完全一致；先读再改 |
| 移动/重命名 | move_file | 目标已存在时拒绝覆盖；只移动文件 |
| 复制 | copy_file | 保留原文件；目标已存在时拒绝覆盖 |
| 新建目录 | make_dir | 父目录自动创建；已存在时返回提示 |
| 删除 | delete_file | 会备份；批量清理才用命令 |
| Word/Excel/PDF/PPT | 专用工具 | 不要把二进制当文本读 |

写之前先读；改之前先确认当前内容。不要用命令批量覆盖内置工具能安全完成的事。

## Git 基本流程

### 1. 看状态

- git status：有哪些修改、未跟踪文件、当前分支。
- git diff / git diff --staged：具体改了什么。
- git log --oneline：最近历史，确认基线。
- 确认没有用户未提交的工作会被你覆盖。

### 2. 提交

- 只暂存本次相关文件；不要用 git add -A 把无关文件、密钥、构建产物一起提交。
- 提交信息说清「为什么改」，而不是复述文件名：
  - 好：修复画布预览在端口未就绪时的空白页
  - 差：update canvas.tsx
- 一个提交只做一件逻辑上的事；大改动拆成可审查的提交。
- 提交后运行 git status 确认工作区干净/剩余内容符合预期。

### 3. 分支

- 新功能/实验用分支；确认当前分支和基线。
- 创建/切换前确认没有未提交改动会被带走或覆盖。
- 合并前先看 diff 和测试；冲突要理解双方意图，不要盲目选择一边。
- 不擅自删除分支、重写历史或强制推送。

### 4. 历史与回退

- 查看历史：git log、git show、git diff commit1..commit2。
- 回退优先用可逆方式：新提交（revert）、备份文件、Morrow 检查点/回退。
- git reset --hard、checkout --、clean -f 会丢失未提交工作；执行前必须确认并优先备份/stash。
- 不修改已发布提交；需要时创建新提交说明修正。

### 5. 身份与配置

- 提交需要用户名/邮箱；Morrow 的 Git 面板可设置仓库级身份，不需要先去终端配置。
- 不修改全局 Git 配置；只改当前仓库时用 --local。
- 不提交 .env、密钥、凭据、用户数据；检查 .gitignore 是否覆盖。

## 何时用终端，何时用面板

- 查看状态/diff/历史、提交、切换分支：优先用 Git 面板或 git 命令，二者等价；以真实仓库状态为准。
- 复杂历史操作、冲突解决、批量检查：终端更灵活，但命令要短小、可解释。
- 用户不熟悉终端时，用面板并说明每一步；不要把一堆命令丢给用户自己跑。

## 提交前检查

- git status 只包含预期文件。
- diff 中没有调试输出、临时文件、密钥、生成物。
- 相关测试/构建通过；或明确说明未运行及原因。
- 提交信息能让人理解动机。
- 分支/远程状态符合预期；没有意外 force push。
- 需要时更新文档/变更记录，而不是只改代码。

## 常见反模式

- 不看 status 就 add -A，把无关文件/密钥提交。
- 用 reset --hard 解决冲突，丢掉用户工作。
- 在主干上直接做高风险实验。
- 提交信息只写「update」。
- 把构建产物、缓存、日志提交进仓库。
- 为了通过 hook 使用 --no-verify（除非用户明确要求并理解后果）。
- 修改全局 Git 身份/配置。
- 删除分支/重写历史前不确认。

## 与其他技能的配合

- 改动审查：code-review。
- 缺陷修复：debugging。
- 交付前验证：verify-before-delivery。
- 发布说明：document-deliverables。
