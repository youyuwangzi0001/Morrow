## 2. 统一运行方式

| 场景 | 命令 | 内容 |
|---|---|---|
| 快速检查 | `npm test` / `npm run test:unit` | 全部 366 项核心单元 |
| 真实界面链路 | `npm run test:e2e` | 自动构建后运行全部 46 条核心 Electron 流程 |
| 统一检查 | `npm run verify` | 类型、UI 规则、覆盖登记、单元及 Electron |
| 覆盖与数量 | `npm run test:suite` | 38 域完整性、核心标记、数量预算 |
| 发布包检查 | `npm run dist:final`，随后 `npm run smoke:packaged` | 构建交付物并验证实际启动、渲染和截图 |

`test:unit:all`、`test:e2e:all`、`verify:all`、`test:eval`、`test:mock` 和专用真实模型探针入口已经移除。直接运行 `npx vitest run` 或 `npx playwright test` 也只会收集核心用例；Playwright 直接运行前需构建。

定位某个功能时可运行对应文件或按核心域筛选：

```powershell
npx vitest run tests/unit/studio-store.test.ts
node scripts/build-for-tests.mjs
npx playwright test tests/e2e/workspace.spec.ts --grep "@core:git"
```

不要在 Electron 测试运行中重建同一个 `out/`。多项工作并行时，为验证建立独立工作区与构建目录，保持源码、测试和资源来自同一快照。

## 5. 维护规则

1. 每个用例直接使用 `@core:功能域` 标题，并在清单中登记功能域。禁止额外扩展套组、未标记用例、整组标记、`.only` 或用参数化方式隐藏数量。清单检查也拒绝恢复旧脚本入口或默认标题筛选。
2. 优先在现有核心流程中补充必要断言。独立的数据安全、权限或主链路行为需要单独验证时，才增加核心用例。
3. 当前维护预算为 **380 项单元、46 条 Electron 流程**。新增后先消除重复；确需扩展核心能力时，说明覆盖并同步预算。
4. 修改模块可先运行对应文件，完成后运行 `npm run verify`。交付物仍须执行打包冒烟。

模型流程使用受控本地响应，应用、IPC、持久化和导入导出走实际实现。真实模型质量、账号服务和长媒体表现由内测反馈及针对性验证评估。本次测试精简本身只调整测试与维护文档；后续 r057 内置漫剧升级已修改生产代码并重新打包。此前功能验收和内测决定保留在 [最终验收文档](MORROW-BETA-ACCEPTANCE-2026-10-30.md)。
