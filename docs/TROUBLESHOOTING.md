# 排障：按现象找原因

每条都按“现象 → 先看什么 → 怎么处理”写。先确认现象，再看第二列指向的设置分页、路径或状态，最后执行第三列的动作。表里没有的情况，用最后一节的方法抓信息。路径与变量含义见 [REFERENCE.md](REFERENCE.md)。

## 目录

| 现象 | 章节 |
|---|---|
| 装不上、双击没反应、数据目录报错 | 安装与启动 |
| 模型连不上，报 401、404、429 或超时 | 模型与连接 |
| 订阅登录、额度或渠道状态不对 | 订阅 |
| 图片、视频、配音、配乐失败 | 多媒体 |
| 终端打不开，Git 操作失败 | 终端与 Git |
| 网页打不开，桌面操作点不到 | 浏览器与电脑操作 |
| 手机连不上或配对失败 | 手机配对与连接 |
| 备份、迁移、换机、卸载 | 数据、备份与卸载 |
| 变慢、上下文被压缩、占用过高 | 性能与上下文 |
| 要找人帮忙定位 | 收集信息 |

## 安装与启动

先确认系统是 Windows 10/11 x64，并分清装的是 NSIS 安装版、便携文件夹版还是单文件便携 exe；三者的数据位置不同。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| SmartScreen 提示“Windows 已保护你的电脑” | 发布包未做代码签名 | 先按 `SHA256SUMS.txt` 校验文件；哈希一致时选“更多信息 → 仍要运行”，不一致就不要运行 |
| 单文件便携版首次启动很慢或停住 | exe 同级是否出现 `.morrow-runtime-*` 与 `Morrow Data` | 首次运行要解压运行时，等它完成；把整个文件夹放在可写目录，不要放 `Program Files` 或只读共享盘 |
| 启动即退出，或提示无法写入数据目录 | 是否已有 Morrow 在运行、磁盘是否已满、目录是否可写 | 退出托盘里的另一个实例；换一个有写权限的目录；仍失败时删除自定义目录指针后重启 |
| 有任务时“更改目录”按钮不可用 | 是否有运行中的对话或后台任务 | 先停止任务再改；用 `--data-dir` 启动时按钮本来就不可用，这是预期行为 |
| 改了数据目录后设置没生效 | `%LOCALAPPDATA%\Morrow\data-location.json` 是否指向新路径 | 重启 Morrow；盘符断开或目录不可写时会回退默认目录，恢复默认后重新选择 |
| 关闭窗口后进程还在 | `设置 › 外观` 的“关闭窗口时” | 改成完全退出，或从托盘图标退出；桌面伙伴是独立窗口，托盘也会保留进程 |
| 卸载后数据还在 | 安装包设置了 `deleteAppDataOnUninstall=false` | 你的数据默认保留；需要彻底清理时手动删除数据目录，先做好备份 |

## 模型与连接

模型错误大多带着 HTTP 状态码，先按状态码分流，再看 `设置 › 模型` 里的服务、Key 与 Base URL。更多接线方式见 [MODELS.md](MODELS.md)。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 提示“API Key 无效或没有访问权限（HTTP 401/403）” | 当前服务与 Key 是否对应，Key 是否过期 | 重新粘贴完整 Key，确认账号有该模型权限，保存后点“测试连接” |
| 提示“接口地址不存在（HTTP 404）” | Base URL 是不是网页地址、是否少了 `/v1` | 填服务商文档给的 API 地址：OpenAI 兼容用 `https://host/v1` 或完整 `/chat/completions`，Anthropic 用 `/v1/messages` |
| 提示“请求太频繁或额度不足（HTTP 429）” | 服务商后台的余额与限流，订阅页的额度 | 等自动重试或换模型；余额不足去服务商后台充值，别反复点发送 |
| 测试连接一直转圈或超时 | 本机网络、代理、DNS；地址是否可达 | 在本机浏览器或 `curl` 访问同一个 Base URL；确认代理覆盖该域名，再回设置里测试 |
| 本机模型没有回复 | 服务是否在跑：Ollama 默认 `127.0.0.1:11434`，LM Studio 默认 `127.0.0.1:1234`，llama.cpp 默认 `127.0.0.1:8000` | 启动服务并加载模型；在模型页填对地址与模型 ID，再点“测试连接” |
| 回复被截断 | 该模型的最大输出设置 | 调大最大输出；订阅模型在订阅详情里改，注意不要超过上下文窗口 |
| 只有思考没有正文 | 服务商是否返回了空内容，是否刚换过模型 | 等内核自动重试；持续出现就换模型，或查看日志里的响应状态 |
| 换模型后上下文变小 | 新模型的可处理长度 | 按模型计算属预期；需要长上下文时换窗口更大的模型，或新建对话 |

## 订阅

订阅的登录态与额度由服务商决定，Morrow 只展示能验证的状态，未验证的渠道不会显示已连接。接入说明见 [MODELS.md](MODELS.md)。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 订阅页显示未连接 | 登录是否过期，登录窗口是否被挡在后台 | 重新登录；Codex、Qoder 与 Agent 订阅可以试“导入本机登录”；登录窗口没出现时再点一次或复制登录链接 |
| 登录成功但模型列表没有新增 | 是否刷新过可用模型 | 点“刷新可用模型”，回到输入框重新选一次模型 |
| 额度用尽或请求被拒 | 订阅页额度、服务商后台的套餐状态 | 等额度重置或换渠道；429 会自动重试，403 通常要重新登录 |
| 导入 Codex 登录失败 | 本机是否存在可读的 Codex 登录文件 | 改用“浏览器登录 ChatGPT”，或直接走 API Key |
| Antigravity 登录失败 | 是否配置了 `MORROW_ANTIGRAVITY_CLIENT_SECRET` | 该 OAuth secret 不内置，需要自己申请并配置后再登录 |
| 渠道显示已连接但请求失败 | 账号是否被风控、是否受地域限制 | 在浏览器里确认账号状态；换网络或换渠道再试 |

## 多媒体

本机生成依赖 ComfyUI 与 FFmpeg，配音还依赖本机 Python 环境；缺什么会明确报错。配置项见 [MEDIA.md](MEDIA.md)。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| ComfyUI 显示未连接 | `设置 › 本地` 的地址（默认 `http://127.0.0.1:8188`）与安装目录 | 先手动启动 ComfyUI，或填好目录后点“启动”；确认端口与设置一致 |
| ComfyUI 启动很慢或显存不足 | 首次加载模型通常要 1–2 分钟；显卡显存 | 等加载完成；降低分辨率或批量，关掉其他占显存的程序 |
| 生成失败，提示缺少工作流或输出节点 | 本机模型条目里的工作流 JSON 与输出节点 ID | 在 ComfyUI 用“保存（API 格式）”导出，粘贴到模型条目，填对输出节点 |
| FFmpeg 不可用 | 系统 PATH 里有没有 `ffmpeg`，或设置里的 FFmpeg 路径 | 安装 FFmpeg 后填绝对路径；它不随 Morrow 内置 |
| 配音没有声音 | 本机 TTS 是否就绪：`%LOCALAPPDATA%\Morrow\local-tts\venv` 与模型目录 | 装好 Python 环境与模型；也可以改用 Windows 系统语音或云端配音 |
| 云端图片、视频或配音不可用 | 对应服务是否保存了 Key | 在“云端多媒体生成”里填 Key 并保存；没有 Key 不会发起请求 |
| 导出的视频没有声音 | 时间线是否有音频轨，FFmpeg 是否可用 | 先补齐音频轨再导出；按上一条修好 FFmpeg |

## 终端与 Git

终端是真实 PTY，Git 面板只做本地操作。默认终端在 `设置 › 终端` 选择，权限档决定能否写入。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 终端打不开，或默认不是 Git Bash | 本机是否装了 Git Bash、PowerShell 7 或 WSL | 安装对应 Shell，在 `设置 › 终端` 点“重新检测”并选择；只影响之后新建的终端 |
| 提示“同时最多运行 16 个终端/后台任务” | 终端面板与后台任务里还开着多少进程 | 结束不用的进程；上限是 16 个运行中进程，已退出记录保留 40 条 |
| Git 操作被拒绝，返回 `READ_ONLY` | 当前权限档 | 只读档拒绝写入与命令；切到询问或完全访问，再重试 |
| Git 面板里找不到 push、pull 或远程 | 面板的能力范围 | 面板只做初始化、status、diff、暂存、放弃、提交、身份、分支、log、show；远程操作用终端执行 |
| 提交时提示缺少身份 | 当前仓库有没有 `user.name` 与 `user.email` | 在 Git 面板填身份并保存，只写入当前仓库 |
| 大仓库状态很慢或 diff 被截断 | 改动文件数量与单个文件大小 | 分批暂存；超长 diff 会截断展示，必要时用终端看完整内容 |

## 浏览器与电脑操作

内置浏览器只接受 http(s)，电脑操作走 Windows UI Automation。两者都有明确的能力边界，遇到拒绝先判断是不是预期限制。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 网页打不开，地址被拒绝 | 地址协议 | 只支持 `http://` 与 `https://`；`file://`、`javascript:`、`data:` 等一律拒绝 |
| 点击新窗口链接没有弹出新标签 | 链接是不是 http(s)，站点是否用了 `target="_blank"` | 内置浏览器不创建新窗口：http(s) 弹窗改为在当前标签打开，非 http(s) 会被拒绝；需要另开页面时用地址栏 |
| 电脑操作点不到控件 | 目标窗口是否在前台、是否被其他窗口遮挡 | 先用 `computer_observe` 拿 UI 树，用 `computer_invoke`、`computer_set_value` 在后台操作；必须真实点击时把窗口置前并保持可见 |
| 操作进行到一半被取消 | 前台窗口是否变化，缩放或分辨率是否变化 | 重新观察窗口与控件引用再操作；不要把目标窗口切到后台 |
| 操作密码、支付或系统设置窗口被拒绝 | 窗口是否属于敏感类别 | 这是预期限制；改用手动操作，或用文件与命令完成同样的事 |
| 截图区域不对 | 窗口位置、尺寸与 DPI 缩放 | 重新 observe 后再截图；坐标按当前前台窗口计算 |

## 手机配对与连接

手机端只做旁观与审批，不执行工具；连接范围仅限同一局域网。完整协议见 [PAIRING.md](PAIRING.md)，功能边界见 [MOBILE.md](MOBILE.md)。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 手机一装好就连不上，桌面也没有任何日志 | 这一版 APK 是否声明了 `INTERNET` 权限 | 0.2.0 的合并清单里没有这条权限，真机发不出连接请求；等修复包，先在桌面端操作 |
| 手机提示配对码里没有连接地址 | 桌面票据是否带 `relayHint` | 0.2.0 的配对面板没有写入该字段，配对无法完成；细节见 [PAIRING.md](PAIRING.md) 的“故障排查” |
| 手机连不上，电脑上没有反应 | `设置 › 手机配对` 的“远程通道”是否打开 | 打开开关；默认关闭，关着时连端口都不会创建 |
| 电脑上生成配对码失败 | 通道是否开启，粘贴的是否以 `MORROWPAIR1.` 开头 | 先开通道，再从手机复制完整配对请求粘贴进来；公钥不完整时也会失败 |
| Windows 防火墙弹窗或直接拦截 | 当前网络是否被识别为“公用” | 允许在专用网络通信；公用网络下不要开放，改用手机热点组建同一局域网 |
| 配对码过期 | 票据是否超过 90 秒 | 重新生成一张，手机上用新的六位码；票据是一次性的，用过的不能再用 |
| 六位码输错 3 次 | 是否连续输错，票据是否已作废 | 重新生成票据；错误 3 次后旧票直接作废 |
| 提示证书指纹不一致 | 手机显示的指纹与桌面的是否一致 | 不要继续连接；在桌面撤销该设备后重新配对，仍不一致就检查是否有中间人代理 |
| 手机与电脑不在同一网段 | 两台设备的 IP 与子网掩码 | 连同一个路由器或同一个 Wi-Fi；跨网段、跨网络都不支持，公网中继未实现 |
| 连接被关闭，关闭码 4401 | 鉴权失败：配对信息不匹配或设备已被撤销 | 撤销设备后重新配对，确认手机用的是本机新票据 |
| 连接被关闭，关闭码 4402 | 加密帧认证失败，密文被改过 | 重装或重配手机端，检查是否有代理改写流量；必要时撤销设备重配 |
| 连接被关闭，关闭码 4403 | 检测到重放，旧帧或乱序帧 | 关掉手机上重复打开的窗口，重启手机端后重连，不要并发多开 |
| 手机切到后台就断线 | 是否正在跟盯长任务；省电策略是否杀了进程 | 跟盯期间由前台服务保活；没有跟盯任务时切后台会主动断开，回前台重连。进程被杀后没有推送，只能回前台补拉 |
| 手机能看到状态但审批没反应 | 桌面端是否在运行，审批是否已超时 | 保持桌面端运行；审批卡有 120 秒倒计时，超时按拒绝处理 |

## 数据、备份与卸载

数据目录的位置与内容清单见 [REFERENCE.md](REFERENCE.md)。迁移前先退出 Morrow，避免复制到一半的文件。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 想备份对话、作品与设置 | 数据目录在哪 | 在 `设置 › 关于` 复制数据目录路径，退出 Morrow 后整体复制；不要只复制 `sessions/` |
| 换电脑后 API Key 不能用 | 密钥由 Windows DPAPI 加密，和当前账户绑定 | 在新机器上重新填写 Key；直接复制 `secrets.json` 不能跨账户解密 |
| 改错内容想回退 | 会话的检查点列表 | 每个普通工作轮次有一个检查点，单会话最多 100 个；回退会同时恢复对话与文件 |
| 更改数据目录失败 | 目标目录是否可写，是否有任务在跑 | 停止任务；目录不可写时恢复默认目录再重选；指针文件损坏可删除后重启 |
| 便携版想搬走 | 是否连同 `Morrow Data` 与运行时目录一起复制 | 一起复制 exe、`Morrow Data` 与 `.morrow-runtime-*`；只搬 exe 会重新解压并可能找不到旧数据 |
| 卸载后想彻底清除 | 安装版还是便携版 | 安装版从“设置 › 应用”卸载，再删数据目录；便携版删除 exe、`Morrow Data`、`.morrow-runtime-*` 与 `%LOCALAPPDATA%\Morrow` 指针 |

## 性能与上下文

上下文占用按当前模型窗口计算，有服务商真实用量时标“API 精确”，否则按文字长度估算。压缩设置与手动压缩在 `设置 › 上下文`。

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 长对话变慢，开始自动压缩 | 上下文占用比例与“自动压缩”开关 | 默认到 80% 触发（可调 50–95%），保留最近 8 条；可点“立即压缩”或新建对话 |
| 占用显示“估算”而不是“API 精确” | 服务商是否在响应里返回 usage | 估算按文字长度算；换用会返回用量的服务商或模型后会变精确 |
| 压缩后忘了前面的约定 | 压缩只作用于模型侧，历史消息还在 | 回看原消息；把长期约束写进项目规则文件，减少重复交代 |
| 任务跑飞或反复重试 | 是否长时间没有进展，是否触发了卡住检测 | 先停止任务；长任务用目标模式写清验收标准，必要时拆成小任务 |
| 内存或磁盘占用高 | 数据目录大小、`tmp/`、作品素材与日志 | 清理临时文件、旧作品与旧日志；单作品上限 512 MB，超限会拒绝 |
| 启动变慢 | 数据目录是否在网络盘，作品数量是否很多 | 把数据目录放本机 SSD；首次便携启动要为解压运行时留时间与空间 |

## 收集信息

反馈问题前把下面几项准备好，能直接缩短定位时间；不要附 API Key、Cookie 或含敏感路径的文件。

1. 版本与运行环境：`设置 › 关于` 里的版本、Electron、Chromium、Node。
2. 安装形态：NSIS 安装版、便携文件夹版或单文件便携 exe；数据目录路径可从同一页复制。
3. 日志：数据目录下的 `logs\main.log`，按时间取对应片段；日志是 JSON 行，5 MB 轮转，保留 3 份。
4. 复现步骤、预期结果与实际结果；涉及模型时附服务商、模型 ID 与 HTTP 状态码。
5. 涉及配对时附关闭码（4401、4402、4403）与是否同一局域网，不要附配对票据原文。
6. 源码构建或打包的问题，附 `npm run verify` 的完整输出；它依次跑 typecheck、audit:ui、audit:flex、docs:check、test:suite、test:unit、test:e2e。构建前置条件见 [DEVELOPMENT.md](DEVELOPMENT.md)。
