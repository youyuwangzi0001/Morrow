v0.2.0 已经很强，
但还没有被“接住”。

现有能力足够支撑长期工作，问题集中在入口、信任和配置成本，而不是缺少又一个工具。

已有，直接复用

来自当前代码与文档，不是规划项。

  • ✓Agent 与 Super-Agent：文件、命令、浏览器、电脑操作、审批、并行成员、独立验收与重试。
  • ✓Studio：中短篇、长篇、漫剧；蓝图、写作、分镜、时间线、配音、配乐、检查与交付。
  • ✓长期资料：项目、知识文件、全局/项目记忆、任务经验、技能、MCP、定时任务、灵动岛。
  • ✓模型来源：订阅登录、API Key、本地 Ollama/llama.cpp/LM Studio；不强制注册账号。
  • ✓恢复基础：检查点、文件历史、会话搜索、归档与数据目录迁移。

需要验证的使用障碍

代码能确认能力缺口；实际影响仍需 Beta 访谈与任务观察验证。

  • ×缺少跨会话摘要：已有会话选择与恢复，但缺少待处理事项、上次进度和最近成品的统一入口。
  • ×首启路径不完整：现有引导以 API Key 为主；订阅在“订阅”，本机模型在“本地”，没有统一首启分流。
  • ×长期数据没有保险：只有数据目录迁移，没有完整备份/恢复和更新前保护。
  • ×能力发现靠猜：项目、模板、配方和导入都已有或可做，但没有“我想做什么”的入口。
  • ×交付完整性需补强：已有工程包导入/导出及发布套组；缺失素材仍可能被跳过，分享前须核对完整性。
  • ×安装信任成本：两个 exe 未签名，SmartScreen 会劝退第一次用户。
边界

不伪造已连接/已验收，不默认上传数据，不加强制账号，不把 token/费用做成硬闸门，不用启发式评分冒充质量审查。

T01

今天 + 接着上次

打开 Morrow 先看到下一步；会话顶部保留“上次做到这里”。

P0留存

实现

  • 先做 Today 最小版：最近会话、未完成目标、最近成品；复用会话/项目/任务元数据，不在渲染层一次读取所有正文。
  • 主进程提供有上限的只读摘要查询（默认最近 20 项），复用现有 store/IPC；T05/T06 共用同一查询与完成状态规则，不建第二套状态数据库。
  • 尊重“恢复上次会话 / 打开 Today”的用户选择；无历史沿用欢迎页。删除、归档、临时会话与缺失工作区分别处理。
  • “继续”只打开对象并展示上下文与权限。失效审批显示已过期；工具结果不确定时要求核对，禁止自动重放命令、付款或外发动作。

验收

  • 卡片能定位到真实对象；删除、归档、重命名后无悬空入口，空状态可新建任务。
  • 退出重开、崩溃中断、流式断连后，已完成/失败/待核对状态不混淆；继续不会重复工具副作用。
  • 首次查询只读元数据；达到 T09-A 的启动与查询预算；键盘可操作且不抢正在输入的焦点。
落点 src/main/session.ts / runtime.ts；src/renderer/features/shell.tsx；src/renderer/store.ts依赖与范围 依赖现有会话/目标状态；T09-A 提供基线。与 T03 可独立开发，不能为了 Today 强行迁移全量数据。
T02

首启三扇门 + 连接医生

订阅、API Key、本地模型三条路都能完成首启；失败时知道改哪一项。

P0增长

实现

  • 首启提供订阅、API Key、本机模型三条路径，复用设置 → 订阅 / 模型 / 本地的服务与状态；不复制认证实现。
  • 先校验地址/本机服务，再由真实请求区分 DNS/TLS/网络、401/403、404/模型不存在、429/额度、超时。只按已知证据诊断，不从单一超时断言 Key 错误。
  • 区分“凭据已保存”“服务可达”“文本回复成功”“工具调用可用”；首个 Agent 任务另外核对工具调用能力。切换服务和取消测试时取消旧请求或丢弃迟到结果。
  • 复用已配置账号；登录由用户完成。可跳过进入离线演示，演示状态与真实连接清楚区分，不自动试遍所有收费模型。

验收

  • API、一个订阅渠道、一个本地服务分别完成真实文本回复；记录日期/应用构建/服务/模型，不能以 mock 替代渠道实测。
  • 三条路径都覆盖取消、重试、401/403、404、429、超时和离线；导入登录不等于已连接。没有测试条件的渠道标为未验证。
  • 切换提供方不串 Key/模型/旧响应，日志和错误导出脱敏；先看演示不产生真实连接成功事件。
落点 src/renderer/features/onboarding.tsx / settings.tsx；src/main/ipc.ts / subscriptions.ts / settings.ts依赖与范围 现有 provider/subscriptions 服务可复用；供应商账号与本机模型是验收环境依赖，不是应用内置能力。
T03

备份与恢复

按真实存储清单备份应用数据与选定素材；预览后恢复到新目录，保留原库可退回。

P0信任

实现

  • 先列持久化清单：会话/检查点/文件历史、项目/知识/记忆、技能/命令/hooks、定时任务、协作元数据、Studio 工程与素材、非敏感设置。按真实存储位置收集，禁止只复制固定七个目录。
  • 个人备份显式声明包含正文及项目路径；用清单白名单排除所有凭据（含加密 Key、OAuth、MCP env/header 密钥）、浏览器登录与缓存。分享时另走 T07 脱敏清单，不承诺私人备份没有私有路径。
  • 发现 Studio 自定义根目录及外部知识/素材。默认备份应用管理数据，工作区源码不等于应用数据；用户选择外部依赖后打包，否则列出未包含项与恢复后重新定位步骤。
  • 备份前检查活跃 Agent/Studio/定时任务，让用户等待结束或主动停止；禁止后台强停。暂停新写入 → flush → 快照 → 恢复服务；以临时文件生成并校验 manifest 的大小、SHA-256、schema 后原子提交。
  • 恢复先解包到隔离暂存目录并校验版本、路径穿越/符号链接、体积与磁盘空间；预览差异并确认。创建恢复前快照，停止写入，按事务日志切换；下次启动能完成或回滚中断事务。
  • v1 只提供整套恢复到独立新目录并切换，保留原目录可退回；不做逐条合并。跨机器重选工作区/外部根目录并重新授权；恢复的 schedules/hooks 默认禁用，待用户逐项启用。

验收

  • 在新数据目录完成备份 → 恢复 → 重启，按清单比对内容/哈希/引用；覆盖自定义 Studio 根目录、中文/长路径、空库、跨机根路径变化。
  • 备份与恢复各阶段注入中断、磁盘不足、损坏哈希、旧/未来 schema 和路径穿越；原库保持可读，不出现部分恢复后自动执行任务。
  • 扫描凭据文件与嵌入式 env/header 字段；导出清单明确缺少的外部资源、不可迁移凭据和不包含的工作区源码。恢复前快照不可用时阻止切换。
落点 新增 src/main/backup.ts（建议）；src/main/workspace.ts / ipc.ts；src/shared/types.ts / contracts.ts；src/preload/index.ts；settings.tsx依赖与范围 P0。先完成存储清单和一致性协议，再做设置按钮；复用数据目录迁移约束，不把现有迁移当作完整备份。
T04

新用户入口：搬家 + 首个成果

先交付可复现的首份报告，再做配置搬家；15 分钟作为指定环境下的观察目标。

P0增长

实现

  • T04-A（P0）先交付一条无需媒体引擎的首成果路线：在用户选定的工作区读取示例资料，产出有来源且可打开的交接报告。整理文件和短篇模板随后复用；漫剧不纳入 15 分钟承诺。
  • 在模型已就绪、资料可读的受控环境，从用户确认任务起计时；下载、注册和模型安装另计。记录成功/失败和真实成品，不拿完成轮次代替成果。
  • T04-B（P1）再导入 MCP/技能/命令：来源 → 解析预览 → 冲突选择 → 事务写入。默认禁用导入的 MCP/自动命令，重新确认信任；不导入 Key、OAuth、环境中的秘密。
  • 复用现有规则发现和命令/技能目录，显示来源；禁止导入时执行 shell、启动服务或自动下载，防止路径穿越与覆盖现有配置。

验收

  • P0：固定夹具和指定模型下生成一份可打开、来源可追溯的报告；5 位首次用户观察记录成功数、中位耗时和失败原因，目标 ≤15 分钟，不保证所有服务网络。
  • 报告不存在/为空/写入失败时不得显示成功；重试复用任务 ID 或提示已存在成果，不重复改动用户文件。
  • P1：取消不写入、重复导入不重复、冲突可预览；恶意配置/超大文件/中断写入不改变现有可用配置。
落点 src/renderer/features/onboarding.tsx / shell.tsx / composer.tsx；src/main/memory.ts / features.ts / agent.ts依赖与范围 T04-A 依赖 T02；可先挂现有欢迎页，随后接 T01。T04-B 依赖 T03 的配置保护与回滚，不与入口改造强绑交付。

  • 备份建议新增 BackupManifest 与预览/执行接口；先注册共享契约、preload 白名单、主进程校验和 renderer 状态，接口名以实现评审为准。全部凭据均排除。
  • 配方复用现有 schedules/hooks/commands，默认禁用；定义重启、错过触发、重试去重及无人值守权限，不新建配方引擎。
  • 导入先做预览接口，不直接写 MCP/技能目录；密钥只在 Morrow 内重新授权。
  • 更新只做检查与下载，不做静默安装；签名是发布依赖，不是 UI 文案。
  • 新增状态必须可失败、可重试、可回退；测试覆盖无模型、断网、损坏数据。

本稿范围建议：v1 备份排除所有凭据；更新手动检查；本地度量默认关闭且无上传。外部依赖：订阅实测账号、测试机、代码签名主体/预算。实现前另评审 schema 兼容与恢复协议。
