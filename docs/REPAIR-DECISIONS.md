## T06 · Token/成本预算闸门：按要求不做

- 结论：**不实现任何硬预算**（不设单次对话、单日或会话级 token/金额上限，不拦截运行、不自动暂停）。
- 决定人：用户。
- 时间：2026-11-02。
- 原因：Morrow 面向的用户中包含程序员，长时间连续开发是常态；硬预算会在长任务中误伤正常使用。
- 已回退：规划期间实现过的预算字段、设置项、运行检查、界面、单元测试与 E2E 已全部删除；仓库中不保留预算代码或隐藏开关。
- 保留内容：用量统计、按天 Token 账本、费用估算与 T07 近 7 日趋势不受影响，仍然只读展示，不做限制。
- 后续约束：除非用户重新提出，任何任务卡都不要再引入 token/费用预算闸门。

## T11 沙箱与 T13 Docker 工具：不新增依赖

- 结论：T11 的命令沙箱与 T13 清单里的 Docker 能力有交集，但**不需要新增 npm 依赖，也不自动安装 Docker**。
- T11 的沙箱是 `run_command` 的可选隔离后端：检测本机 Docker、要求 Linux 容器与预拉取镜像；没有 Docker 时如实降级为当前终端，并在审批卡明示。
- T13 的 Docker 项是「让 Agent 操作容器」的工具能力，与本卡沙箱不是同一功能；T13 已明确没有为凑清单接入未验证的 Docker 工具。
- 完整隔离也可以走各平台原生机制（Windows AppContainer/Job Objects、Linux namespace/bubblewrap），但需要原生模块与分平台验证，成本和失败面都明显高于可选 Docker；当前不采用。
- Docker Desktop 是用户自行决定的外部前置（体积、管理员权限、许可与 WSL2 都由用户掌控），Morrow 不静默安装、不自动拉镜像。
- 后续如需补 T13 的 Docker 工具，仍只调用用户已安装的 `docker` CLI，不引入新的 Node 依赖；可评估 Podman 兼容，但不在本轮范围。
